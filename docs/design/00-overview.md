## Ключевое архитектурное решение (общее для обоих треков)

Оба трека упираются в один и тот же рефакторинг: сейчас `voice_tray.py` —
монолит, в котором GTK, xclip, PyAudio, Groq и faster-whisper переплетены.
Прежде чем делать что-либо из треков, монолит разбивается на ядро и
заменяемые бэкенды:

```
voice_tray/
├── core/
│   ├── app.py            # state machine: Ready → Recording → Processing → Ready
│   └── config.py         # ~/.voice_to_text/, prompt.txt, log
├── audio/                # запись (sounddevice), ring buffer, уровни
├── transcribe/           # интерфейс Transcriber
│   ├── groq_api.py       #   облако (legacy, opt-in)
│   ├── fw_batch.py       #   faster-whisper, целиком файл (как сейчас)
│   ├── fw_streaming.py   #   faster-whisper + LocalAgreement (трек 3)
│   └── gigaam.py         #   GigaAM-v3 через onnx-asr (кандидат, трек 3)
├── platform/             # интерфейсы Tray / Clipboard / Trigger
│   ├── linux_gtk.py      #   текущий GTK+AppIndicator код переезжает сюда
│   ├── macos.py          #   rumps + pbcopy + unix socket (трек 1)
│   └── windows.py        #   pystray + named pipe (трек 1, опционально)
└── __main__.py           # CLI: запуск, --toggle, выбор бэкендов
```

Один рефакторинг обслуживает оба трека: новый транскрайбер — это ещё один
файл в `transcribe/`, новая платформа — ещё один файл в `platform/`.

## Не-цели (пока)

- Никакого GUI-конфигуратора — конфиг остаётся файлами в `~/.voice_to_text/`.
- Не переписываем на другой язык/стек (Tauri, Swift и т.п.) — Python остаётся.
- Мобильные платформы не рассматриваем.
- Автопасту не возвращаем — политика «только clipboard» сохраняется (безопасность).
